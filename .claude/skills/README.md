# Med Spa Site Rebuild — Claude Code Skills

Three installed skills plus an orchestrator, wired together to take a scraped list of Google Business Profiles (med spas, salons, wellness clinics) and output bilingual (ES/EN) Next.js websites that are ready to pitch through GoHighLevel.

## What each skill does (plain English)

### 1. `design-system-generator`

**Plays the role of: brand archaeologist.**

Given an existing website URL, it opens the page in a headless browser, reads the real CSS (`getComputedStyle`), and writes down the actual fonts, colors, spacing, border radii, and shadows the business is currently using. It saves a full spec (`designsystem.md`) and a visual showcase (`showcase.html`) that renders with the original `.woff2` fonts so the preview looks right.

Why this matters: the rebuild needs to keep the client's existing brand equity — their logo color, their fonts — but fix everything else. This skill tells us what to preserve.

### 2. `ui-ux-pro-max`

**Plays the role of: art director.**

Reads the industry ("med spa / beauty / wellness / medical aesthetic") and returns a complete target design system: the right color palette, a typography pairing, spacing scale, the UI style that fits the vertical (e.g. "editorial luxury" vs. "clinical trust"), plus a list of anti-patterns to avoid (emojis as icons, generic beige, etc.).

It's essentially a rulebook that keeps the output from looking like every other WordPress template.

### 3. `web-builder`

**Plays the role of: construction crew.**

Given a business URL or Google Business Profile and a design system, it:
- Downloads the real photos, logo, and assets from the business's site + GMB
- Generates a full multi-page Next.js 15 site (App Router, TypeScript, Tailwind, Framer Motion)
- Includes SEO structure baked in: `generateMetadata`, `sitemap.ts`, `robots.ts`, Schema.org JSON-LD (`LocalBusiness` / `MedicalClinic` / `FAQPage`), Open Graph
- Outputs a statically exportable build you can deploy to Vercel for a live preview OR drop into GoHighLevel as HTML

## The recommended order

```
GMB URL (input)
      │
      ▼
┌─────────────────────────────────────┐
│ 1. design-system-generator          │  ← extract current brand tokens
│    (Mode 2: Extract from URL)       │    designsystem.md + showcase.html
└─────────────────────────────────────┘
      │
      ▼
┌─────────────────────────────────────┐
│ 2. ui-ux-pro-max                    │  ← decide target design
│    python3 search.py "beauty spa    │    target-designsystem.md
│    wellness" --design-system        │
│    --persist -p "<Brand>"           │
└─────────────────────────────────────┘
      │
      ▼
┌─────────────────────────────────────┐
│ 3. web-builder                      │  ← construct the site
│    (feed business URL + design      │    sites/<slug>/ (Next.js source)
│    system + download photos)        │    sites/<slug>/out/ (static export)
└─────────────────────────────────────┘
      │
      ▼
  push to branch  →  Vercel preview  →  GHL pitch
```

**Why this order:** each skill feeds the next. Skipping step 1 loses brand equity. Skipping step 2 gives you a generic template. Skipping step 3 leaves you with a spec but no code.

## How to run it

### Single site

From the repo root:

```
/medspa-rebuild <gmb-url-or-website-url> [optional-slug]
```

See `.claude/commands/medspa-rebuild.md` for the full step-by-step. Claude Code will invoke each skill in order.

### Batch (multiple GMB pages)

You have a list of med spas. Put the URLs one per line in `sites/queue.txt`, then run:

```
bash .claude/skills/run-batch.sh
```

This iterates the queue and runs the full workflow for each URL, one branch per business.

## Bilingual (ES + EN)

The default `web-builder` templates are French. The orchestrator overrides this and configures `next-intl` with:

- `es` as the default locale (target market: Spain)
- `en` as the secondary locale
- `hreflang` tags so Google ranks the right version per region
- Route structure: `/` (Spanish) and `/en/` (English)

Navigation labels are set in `sites/<slug>/messages/es.json` and `en.json`. Copy is generated by Claude from the business's existing site content in Phase 3.

## GHL (GoHighLevel) delivery

Two options depending on what the client wants:

**Option A — deployed site (recommended for pitching):**
Push the branch, connect Vercel, share the preview URL. Most persuasive deliverable.

**Option B — HTML import into GHL:**
After `pnpm next export`, the `sites/<slug>/out/` directory is static HTML. Zip it, import into GHL's website builder, keep their funnel tracking intact.

The `{{BOOKING_URL}}` placeholder in every CTA lets GHL inject their own funnel URL without you touching the code.

## What to check before pitching

- Google Business Profile has 6+ usable photos (if not, the rebuild will look thin)
- The client's existing primary color is preserved
- Schema JSON-LD validates at https://validator.schema.org/
- Lighthouse: LCP < 2.0s, CLS < 0.05
- Mobile sticky "Reservar Cita" / "Book Now" button works
- All images are WebP / AVIF and lazy-loaded below the fold

## Caveats

- The skills are provided as SKILL.md specs and Python helpers. They run when Claude Code actually invokes them during the `/medspa-rebuild` flow — this repo just *hosts* them.
- `ui-ux-pro-max` requires Python 3. Check with `python3 --version`.
- The `web-builder` downloads photos via `curl`. If a site blocks crawling (403), you'll need to manually provide photos in `sites/<slug>/public/images/`.
- These are community skills (see source repos in `.claude/skills/*/README.md`). Inspect before using on production client work.
